VXLAN・EVPN

56%

L2 のフレームを UDP で包んで、IP ネットワークの向こうへ運ぶ。包む・ほどく係が VTEP。

  • VXLAN：元のイーサネットフレームに VXLAN・UDP（宛先 4789）・IP のヘッダを付ける。L3 の上に L2 を作る技術。
  • VNI（24ビット・約1600万）で L2 ネットワークを区別する。VLAN ID（12ビット・4094）の不足を解消する。
  • BUM（Broadcast・Unknown unicast・Multicast）は宛先の VTEP を1つに決められない → 同じ VNI の全てのリモート VTEP へ送る（マルチキャストか、1台ずつユニキャストで複製）。
  • EVPN：MP-BGP で MAC アドレス・VNI・VTEP の IP を事前に配る（コントロールプレーンで学習）。宛先 MAC を知っているので Unknown unicast のフラッディングが減る。
  • VTEP のアドレスにループバックを使うのは、物理インタフェースが1つ落ちても、別の経路で同じアドレスのまま動き続けられるから。

落とした論点 → こう書く

  • IP→外側 IP ヘッダの内側は UDP。VXLAN は L3 の上に L2 を作る
  • 他の VTEP に対して→同じ L2 ネットワーク（VNI）の全てのリモート VTEP へ
  • 不用意なマルチキャストを防ぐ→ループバックは物理インタフェースの障害でも到達できるから
  • スイッチの MAC→学習するのは VM の MAC・VNI・相手 VTEP の IP の3点
  • BUM フレームによって学習→EVPN は MP-BGP で事前に学習（順序が逆）

覚え方：VXLAN は「L2 の手紙を UDP の封筒に入れる」。封筒の差出人（外側 IP）を見れば、相手の VTEP が分かる。

マルチキャスト

58%

送信元は1本送るだけ。欲しい人がいる方向にだけ、途中の機器が複製して届ける。

  • ユニキャストの欠点：受信者の数に応じて、送信元の通信量（負荷と帯域）が増える。
  • IGMP（IPv6 は MLD）＝端末とルータの間。「このグループが欲しい」（Report／Join）、「もう要らない」（Leave）。
  • PIM＝ルータとルータの間の経路制御。PIM-SM は RP を経由する共有ツリー（*,G）、SSM は送信元を指定する（S,G）。
  • IGMPv2 はグループアドレスだけで参加（*,G）→ 送信元ごとにグループアドレスを分ける必要がある。IGMPv3 は送信元も指定できる（S,G）→ 同じグループアドレスでも区別できる。
  • L2SW は普通、マルチキャストを全ポートへフラッディングする。IGMP スヌーピングで「グループアドレス × Join を受けたポート」の表を作り、要るポートにだけ流す。

落とした論点 → こう書く

  • ブロードキャスト→L2SW が全ポートへ転送する動作はフラッディング
  • グループ→IGMPv3 の Report の宛先は 224.0.0.22（マルチキャストアドレス）
  • マルチキャスト→ルータ間で動かすのは PIM-SM、送信元を指定するのは SSM
  • 通信量が肥大化→「受信者の数に応じて送信元の通信量が増加する」と主語と比例関係を書く
  • （*,G）と（S,G）：v2 はグループだけ → 送信元ごとにアドレスを分ける、v3 は送信元で区別できる

覚え方：IGMP は「客と店」、PIM は「店と問屋」。スヌーピングは「店の中の配膳係」。

DMZ・認証

58%

「誰が・何を持っているか・何を確かめたか」で答えを組み立てる。

  • DMZ：公開サーバを内部 LAN から分ける。目的は「公開サーバが侵入された場合に、そこを踏み台に内部 LAN へ被害が広がるのを防ぐ」。
  • 認証＝利用者が本人であることの確認。認可＝操作ごとに権限があるかの確認。
  • ケルベロス：鍵はすべて共通鍵。KDC が TGT を発行し、TGT と引き換えにサービス用のチケット（ST）を発行する。ST はサーバの鍵で暗号化されているので、PC は中身を読めず、書き換えられない。
  • SAML：SP が利用者を IdP へリダイレクトし、IdP が署名したアサーションを SP が検証する。IdP が複数あるなら、SP は先に利用者の所属（どの IdP か）を知る必要がある。
  • デジタル署名で分かること：作成者が正しいこと（真正性）と改ざんされていないこと（完全性）。

落とした論点 → こう書く

  • DMZ に制限され、不正アクセスのリスクを低減→公開サーバが侵入された場合に、内部 LAN の端末まで侵入されるリスク
  • 登録ユーザか判定→認証は本人であること、認可は操作ごとの権限
  • ケルベロスの鍵→共通鍵（公開鍵ではない）。答えには対象（ST）を入れる
  • 署名を検証して分かること→正規の IdP が作成し、改ざんされていない
  • 「図中の字句を用いて」→機器名は図の名前をそのまま写す

L2・パケット取得

59%

スイッチの転送のしかたと、パケットを「どこから・どれだけ」取り込めるか。

  • L2SW は宛先 MAC を学習済みならそのポートへ、未学習なら受信ポート以外の全ポートへ送る＝フラッディング（ブロードキャストは宛先が全ビット1のフレームの名前）。
  • ミラーポート：送信と受信を1本のポートにまとめて複製する → 送受信の合計がポートの速度を超えると取りこぼす。
  • ネットワークタップ：配線から方向ごとに別のポートへ複製する → 両方向とも上限まで取れる。
  • プロミスキャスモード：NIC が自分宛てではない（宛先 MAC が自分と違う）フレームも受け取る。
  • 保存容量＝ビット/秒 × 86,400 秒 × 日数 ÷ 8（バイトへ）。例：100k ビット/秒 × 86,400 × 365 ÷ 8 ≒ 394G バイト。

落とした論点 → こう書く

  • ブロードキャスト→スイッチの動作はフラッディング
  • 大量トラフィックでは難しい→送信と受信の合計で 1G ビット/秒までしか取り込めない（数値と「合計」を入れる）
  • ○○宛てではないフレーム→宛先 MAC アドレスが自分の NIC と異なるフレーム
  • 容量計算で答えが半分になった→式を書き出し、86,400 秒と÷8を1つずつ確認

IPv6

60%

IPv4 の仕組みと1対1で対応させると覚えやすい。ブロードキャストは無く、マルチキャストで代わりをする。

やることIPv4IPv6
相手の MAC を知るARP（ブロードキャスト）NDP の NS/NA（マルチキャスト）
アドレスの自動設定DHCPRS → RA でプレフィックスを知り SLAAC（DHCPv6 も可）
デフォルトゲートウェイDHCP で配るRA の送信元の LLA
アドレスの重複確認GARPDAD：使う予定のアドレスで NS → NA が来なければ使う
経路表のネクストホップ隣のルータの IP隣のルータの LLA（fe80::）
外からの通信を防ぐNAPT が副次的に防いでいたNAPT が無い → FW で外からの通信を制御
MTU の調整Fragmentation NeededPacket Too Big（ルータは分割しない）
  • LLA（fe80::/10）は同じリンクの中だけで有効。ルータを越えない。
  • Modified EUI-64：MAC（48ビット）の真ん中に FFFE（16ビット）を入れて64ビットにし、U/L ビットを反転する。
  • ランダムなインタフェース ID：アドレスが変わるので、ログから PC を特定しにくい（プライバシーとは裏表）。
  • デュアルスタック：IPv6 で失敗すると IPv4 にフォールバックし、同じページが見えてしまう → IPv6 の障害に気付きにくい。
  • 機器間のリンクを LLA だけにすると、外から宛先にできない（守れる）。GUA を付けると traceroute6 で機器を区別しやすい。

落とした論点 → こう書く

  • MAC は 24 ビット→MAC は 48 ビット（24 ビットは OUI だけ）
  • 同一のネットワーク→LLA の範囲は同一リンク（データリンク層で通信できる範囲）
  • DHCP サーバで管理が難しい→SLAAC は PC が自分でアドレスを作る。困るのは PC を特定しにくいこと
  • ネクストホップに宛先のプレフィックス→隣接機器の LLA
  • マルチキャストが届かないか確認→DAD の目的はアドレスの重複がないことの確認
  • データサイズの大きいパケット→PMTUD が検出するのは経路上で最小の MTU

NAPT・回線

60%

NAPT は「変換表」の装置。表が埋まると、新しい通信だけが失敗する。

  • NAPT は（内側の IP・ポート）⇔（外側の IP・ポート）の組を変換テーブルに1行ずつ持つ。
  • テーブルが枯渇すると、空きがないときに始めた通信だけが失敗する → 症状は「一部の・不特定の端末だけ」。帯域不足なら全員が遅くなる。
  • UDP には終わりの合図（FIN）が無いので、保持時間が過ぎたら消す。QUIC（HTTP/3）が増えたら UDP の保持時間を短くして、使われなくなった行を早く消す（短すぎると通信中の行も消える）。
  • ベストエフォート型（速度は努力目標）⇔ 帯域確保型（速度を保証）。
  • サブネットの計算：オクテットの途中で区切れるときは2進数にする。255.240.0.0（/12）なら第2オクテットは16刻み → 172.16.0.0〜172.31.255.255。

落とした論点 → こう書く

  • 原因の説明で「何が起きるか」が抜けた→本文の症状（画面が表示されない）と原因（テーブルの枯渇）をつなげる
  • コネクション維持時間が減り、確立が安定→効果は使われなくなったエントリーを早く削除できる。UDP は「フロー」
  • 直接計測→ベストエフォートの反対は帯域確保型
  • 172.16.255.255→/12 なので最後は 172.31.255.255

IoT・CoAP

61%

CoAP は「UDP の上で動く軽い HTTP」。UDP の弱点を CoAP と DTLS がどう補うかが問われる。

  • LPWA＝Low Power, Wide Area（低消費電力・広域）。LTE-M・NB-IoT はセルラー系で標準化は 3GPP。Wi-Fi は IEEE。
  • ISM バンド（2.4GHz 帯など）は免許不要。Wi-Fi・Bluetooth・電子レンジと共用なので干渉しやすい。
  • UDP では、パケットが順不同・重複・消失しうる。CoAP はメッセージ ID で重複を見分け、後から来た方を無視する。
  • DTLS の cookie：正しい cookie が返れば、ClientHello の送信元が偽装されていないと分かる。不正なら大きな応答を返さず打ち切る（返すとリフレクション攻撃の踏み台になる）。
  • 多数の機器が一斉に送らないようランダムに待つ → サーバとネットワークの両方で負荷の集中を避ける。

落とした論点 → こう書く

  • 不連続・破損→UDP で起こるのは順不同・重複・消失
  • 攻撃者の IP を偽装・SYN Flood→送信元を攻撃対象の IP に偽装、手法はリフレクション攻撃
  • 送信元が正しいかを判断する→「偽装されていないと判断できる」と言い切る
  • 認証情報の発行→HTTP が多いのは TCP の接続確立と切断の分
  • サーバ負荷を軽減→サーバとネットワークの両方の負荷集中を避ける

メール（SPF・DKIM・S/MIME）

62%

SPF は「どの IP から送ったか」、DKIM は「どのサーバが署名したか」。どちらも送信者個人は保証しない。

  • SPF：送信ドメインの DNS（TXT）に送ってよい IP アドレスを書く。受信側は接続してきた IP と照合する。登録するのは外から見える IP（NAT 後のグローバル IP・中継サーバ）。ドメイン名は SPF レコードを引くための検索キーにすぎない。
  • DKIM：送信サーバが秘密鍵で署名し、公開鍵は DNS の TXT に置く（証明書は使わない）。秘密鍵は正規のサーバしか持たない → 検証できれば正規のサーバから送られたと分かる。
  • DKIM の鍵を組織や中継サーバごとに分ける → 1つが漏れても、他の署名・検証には影響しない。
  • SPF・DKIM が保証するのはサーバ・ドメイン。乗っ取られたアカウントからのメールも同じサーバから送られるので通ってしまう → 個人の確認は S/MIME（送信者の秘密鍵で署名、証明書の公開鍵で検証）。
  • PTR（逆引き）だけでは弱い：攻撃者は自分の逆引きゾーンに好きな FQDN を書ける → 正引きして IP が一致するかも確かめる。

落とした論点 → こう書く

  • SPF に登録する IP→受信側から見えるグローバル IP（社内のプライベート IP ではない）
  • SPF で照合するもの→送信元 IP アドレスが SPF レコードに含まれるか（ドメイン名ではない）
  • DKIM の公開鍵の置き場所→DNS の TXT レコード（CA の証明書ではない）
  • 正規のサーバから送られたと分かる理由→秘密鍵は正規のサーバだけが持つ → 公開鍵で署名を検証できる → 正規
  • SPF/DKIM で防げないもの→正規のメールもなりすましメールも同じサーバから送られる場合

続きは R6午後Ⅱ問2（メール）の解答記録で。

BGP

64%

BGP は AS どうしの経路交換。AS_PATH を右から読めば、経路の生まれた場所が分かる。

  • eBGP＝異なる AS 間、iBGP＝同じ AS 内。プライベート AS 番号は 64512〜65534（2バイト）。
  • AS_PATH は経由した AS が左に追加される → 右端が発信元、左端が隣の AS。自分の AS 番号を含む経路はループとみなして捨てる。
  • 全拠点が同じ AS 番号の IP-VPN：そのままだと拠点同士の経路を捨ててしまう → as-override（PE が顧客の AS を自分の AS に置き換える。数は変わらない）。
  • ルートリフレクタ：iBGP のフルメッシュが要らなくなり、ピアの数を減らせる。2台で冗長化するときはクラスタ ID でループを防ぐ。
  • 不正な経路を受け入れると、自分がその宛先へ送る通信が誤った方へ行き、正規の宛先に届かなくなる。
  • RTBH の利点は位置：攻撃を攻撃元に近いところ（入口）で捨てるので、FW や LB まで届かない。

落とした論点 → こう書く

  • 負荷が高まる／不正な経路へ誘導→影響はそのアドレスブロックへ届かなくなる
  • BGP ルータより内部への通信を遮断→RTBH は攻撃元に近いところで遮断できる（比べる軸は位置）
  • コンテンツ→CE の C は Customer（PE＝Provider Edge）
  • mBGP→AS 間は eBGP
  • 64500（1つだけ）→as-override は置き換えなので 64500 64500（長さは同じ）
  • 経路情報を共有できる→ルートリフレクタの利点は iBGP のピア数を減らせる

OSPF・VRRP

69%気になる分野

OSPF は「地図（LSDB）を全員で共有して、各自が最短経路を計算する」。VRRP は「2台で1つの仮想ゲートウェイを演じる」。

  • 流れ：LSA を交換 → LSDB（リンクステートデータベース）を作る → SPF（ダイクストラ法）で自分を根にした最短経路のツリー → 経路表。
  • エリア0＝バックボーンエリア。他のエリアは必ずここにつなぐ。ルータ ID＝OSPF が動く各機器を1台ずつ識別する32ビットの値（落ちないループバックを使う）。
  • コストは宛先へ向かう途中の出力インタフェースの値だけを足す。ECMP は複数の経路の合計コストを同じにする。迂回させたい機器はコストを最大値（65535）に。
  • ECMP はフロー単位（アドレスのハッシュ）で振り分けると、同じ通信が同じ経路を通る → 到着順序が逆転しにくい。
  • BGP などからの再配布経路は Type5（AS 外部 LSA）で流れ、作るのは再配布したルータ（ASBR）。両方向に再配布するとルーティングループの恐れ。
  • ネイバー認証：不正なルータと隣接して経路を交換してしまうのを防ぐ。
  • VRRP：2台のルータが仮想 IP・仮想 MAC（00-00-5E-00-01-VRID）を共有し、PC はそれをデフォルトゲートウェイにする。VRID は 8ビットで 1〜255。
  • マスタだけが定期的にアドバタイズメントを送る。バックアップは、それを一定時間受信しなくなったらマスタの障害と判断する（問い合わせはしない）。
  • トラッキング：上位リンクの障害を検知したら、自分の優先度を下げる → 相手が相対的に上回ってマスタになる（相手の値は変わらない）。
  • プリエンプト：優先度の高いルータが復帰したらマスタを取り返す。プリエンプトディレイは OSPF の経路が収束した状態になるまで待つため（待たないと経路のないまま受けて捨てる）。
  • GARP：切り替わったとき、新しいマスタがGARP（自分の IP を問い合わせる ARP）を送り、L2SW の MAC アドレステーブルを更新させる → 仮想 MAC 宛てのフレームが新しいマスタのポートへ流れる。PC の ARP テーブルは仮想 MAC のままなので変えなくてよい。

落とした論点 → こう書く

  • 管理 ID／ルーティングの優先順位→ルータ ID が識別するのは OSPF が動く各機器
  • 余分に通信が発生しない→認証は不正なルータと隣接・経路交換しないため
  • リンクステート／ルーティング→データベースは LSDB、ツリーは最短経路のツリー
  • コストを2倍で計算→足すのは行きの出力インタフェースだけ
  • 同一コストで負荷分散→目的は2つの回線を通常時から両方使うこと（同一コストは手段）
  • Type5 の生成元に経路の発信元を書いた→作るのはOSPF に再配布したルータ（ASBR）
  • 4096→VRID は 1〜255（4096 は VLAN ID）
  • マスタに広告を出して応答がない→マスタのアドバタイズメントを受信しなくなったとき
  • 相手の優先度が高くなる→トラッキングは自分の優先度を下げる
  • リンクステートの更新を防ぐ→プリエンプトディレイは OSPF の経路が収束した状態を待つ

覚え方：VRRP は「マスタが『生きてるよ』と言い続け、止まったら予備が代わる」。代わったら GARP で「この MAC は今こっち」とスイッチに知らせる。

SNMP・運用（ログ）

75%気になる分野

SNMP は「取りに行く（ポーリング）」と「知らせてもらう（トラップ）」の2通り。ポート番号と、カウンタの読み方が狙われる。

  • マネージャ（監視サーバ）がエージェント（ルータ・スイッチ）の MIB（OID で識別する管理情報の木）を読み書きする。
  • ポート：GetRequest・SetRequest はエージェントの UDP/161、Trap はマネージャの UDP/162。
  • ポーリング：定期的に取りに行く → 間隔の分だけ検知が遅れるが、取りこぼしは分かる。トラップ：異常時にすぐ届くが、UDP なので失われても気付けない → 確認応答のある Inform（v2c 以降）を使う。
  • 回線の利用率：ifInOctets などは累積のカウンタ。2回取得して差分 × 8 ÷ 取得間隔 ÷ 回線速度。32ビットのカウンタは 1G ビット/秒だと約34秒で一周する → 64ビットの ifHCInOctets を使う。
  • セキュリティ：v1・v2c のコミュニティ名は平文で流れる → v3（USM）で認証と暗号化。マネージャの IP アドレス以外からのアクセスを ACL で拒否する。
知りたいこと使うもの
複数機器のログを並べるNTP（UDP/123）で時刻を合わせ、時系列で突き合わせる
ログを1か所に集めるsyslog（UDP/514、RFC 5424）
IP アドレス → どの PC かDHCP のリースログ（いつ・どの IP を・どの MAC に）
誰が使ったか認証ログ（RADIUS：UDP/1812）
到達確認ping＝ICMP のエコー要求とエコー応答

落とした論点 → こう書く

  • 正確な日時にするため→NTP の目的は複数機器のログを時系列で突き合わせること
  • 認証ログ／スイッチのシステムログ→IP から PC を特定するのは DHCP のリースログ
  • 514 と 1812 を入れ替えた→514＝syslog、1812＝RADIUS
  • HTTP→ログ転送のプロトコルは syslog
  • 応答→ping の応答はエコー応答と種類まで書く

覚え方：SNMP は「161 で聞く、162 で叫ぶ」。syslog は 514、NTP は 123、RADIUS は 1812。
